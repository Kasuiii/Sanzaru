# Custom model integration 2.2 — ขอบเขตการตรวจ

- TypeScript และ production build
- ชุดทดสอบกติกา/API ของ SANZARU และ classic เดิม
- สัญญา client: API URL, HTTPS, class coverage, JSON, freshness, duplicate timestamps,
  confidence ที่ตรงกับคลาส, ท่าเปลี่ยนต้องไม่ใช้คะแนนใหม่กับชื่อท่าเก่า,
  และการคงพฤติกรรมชาร์จของ classic
- Python unittest: detection/classification mapping, hand association, neutral,
  load config, image decode/limits, CORS, token, missing weights/classes, busy inference
- Ultralytics adapter ทดสอบกับโครงสร้าง Results จำลองทั้ง detect และ classify

คำสั่งทดสอบเว็บ: pnpm typecheck, pnpm test, pnpm build
คำสั่ง Python ใน ai-server:
  python -m pip install -r requirements-test.txt
  python -m unittest -v test_service.py

ตรวจ Python ด้วย Python 3.12, FastAPI 0.143.3 และ httpx 0.28.1
ไม่ได้ติดตั้งหรือรัน PyTorch/Ultralytics กับ weights จริง เนื่องจากยังไม่ได้รับ .pt
ไม่มีการทดสอบ browser/camera/GPU/Pi แบบครบวงจร หรือผลความแม่นยำของโมเดลผู้ใช้
requirements เป็นช่วงเวอร์ชันสำหรับเริ่มต้น ให้บันทึก environment ที่เข้ากับโมเดลจริงเมื่อทดสอบผ่าน

ตรวจด้วยมือก่อนใช้โมเดลจริง:
1. โมเดลโหลดใน Python และชื่อคลาสครบ
2. หน้าคิคาซารุเชื่อม API ได้ และภาพถูกส่งเฉพาะหลังเลือก custom/เปิดกล้อง
3. ทำนายแต่ละท่า/neutral/มือหาย และทดสอบหลายคน/แสง/ระยะ
4. ปิด API ระหว่างถือท่า: ต้องไม่ร่ายจากผลภาพเก่าหรือ fallback อัตโนมัติ
5. ทดสอบร่ายครบสูตรกับเพื่อนจริง และบันทึก latency/accuracy ตามคู่มือ
6. ตรวจเมนูโมเดลบนจอแคบ และข้อความแจ้งการส่งภาพ

# การทดสอบ SANZARU — Three Wise Monkeys

## ตรวจระบบอัตโนมัติ

```sh
pnpm typecheck
pnpm test
pnpm build
```

ชุดทดสอบใช้ SQLite ในหน่วยความจำและจำลองที่เก็บเสียง ไม่เชื่อมบริการภายนอก
ตรวจผู้เล่น 3 คนพร้อมกัน, การซ่อนตำรา/ตราบอส, สิทธิ์ของแต่ละบทบาท,
ช่องแชตและเสียงที่ต้องผ่านคนกลาง, คิวข้อความและการส่งซ้ำ,
วงจรถูก/ผิดลำดับ, ท่ามือถูก/ผิด, ชนะครบ 5 ผนึก, แพ้, พักเกม,
กลับมาเมื่อหลุด, สลับบทบาท, เริ่มรอบใหม่ และออกจากห้อง

## ตรวจบนเครื่องหลังติดตั้ง

เปิดเซิร์ฟเวอร์ด้วย `pnpm start` แล้วเปิดอีก terminal:

```sh
pnpm test:local
```

คำสั่งนี้ตรวจหน้าเว็บและไฟล์โมเดล แล้วสร้างห้องทดสอบจริงกับเซิร์ฟเวอร์
บน `http://127.0.0.1:8787` ใช้ผู้เล่น 3 คน ตรวจการร่ายหนึ่งผนึก
ตรวจสิทธิ์ข้อความเสียง แล้วปิดห้องทดสอบเมื่อเสร็จ
ต้องรัน `pnpm setup:local` มาก่อน และเปิดเซิร์ฟเวอร์ค้างไว้

## ขอบเขตเพิ่มในเวอร์ชันสามวานร

`tests/ritual.test.mjs` เรียก API handlers ด้วยผู้เล่นแยก token และ SQLite ในหน่วยความจำ
พร้อมตัวจำลอง R2 ตรวจว่า:

- มิซารุไม่มี target/manual; คิคาซารุไม่มี manual; อิวาซารุไม่มี target
- อิวาซารุส่ง free-text ไม่ได้ แม้เรียก API เอง
- ส่งแผ่นลำดับจุดและท่ามือได้เฉพาะอิวาซารุ→มิซารุ
- ข้อมูลชนิดผิด จุดนอก 1–9 จำนวนจุดผิด และท่าที่ไม่มีจริงถูกปฏิเสธ
- ฟิลด์แทรกเพิ่มเติมไม่ถูกเก็บในแผ่นสัญลักษณ์
- คิคาซารุไม่เห็นแผ่นคำตอบจากอิวาซารุ ต้องรับคำบอกจากมิซารุ
- การส่งซ้ำไม่สร้างข้อความซ้ำ และคิวแบ่งข้อความตาม rate limit
- อิวาซารุอัปโหลดเสียงไม่ได้; มิซารุส่งเสียงถึงคิคาซารุไม่ได้
- คิคาซารุดาวน์โหลดเสียงไม่ได้ รวมเสียงที่ตนส่ง
- มิซารุและอิวาซารุฟังคลิปในช่องที่ตนมีสิทธิ์ได้
- คำขอเสียงที่ถูกปฏิเสธไม่ทิ้งวัตถุลงในที่เก็บเสียง
- เล่นครบ 5 ผนึกชนะ, พลาด 5 ครั้งแพ้, พัก/กลับมาเล่น/เปลี่ยนบทบาท/เล่นใหม่ยังทำงาน

การผ่านชุดนี้ไม่ยืนยันความแม่นยำ AI หรือการใช้งานกับกล้องจริง

## เช็กลิสต์การเล่นจริงสำหรับ 3 คน

1. เปิดคนละโปรไฟล์ ตั้งชื่อ เลือกตัวละครคนละตน กดพร้อมและเริ่ม
2. มิซารุเห็นสองช่องสนทนา แต่ไม่เห็นตำราหรือภาพตราอสูร
3. คิคาซารุเห็นตราและวงจร อ่านคำตอบของมิซารุได้ และไม่มีตัวเล่นเสียง
4. อิวาซารุเห็นตำรา มีปุ่มจุด 1–9 กับท่าปิดผนึก แต่ไม่มีช่องพิมพ์หรือไมค์
5. ลองลบจุดล่าสุด ล้างแผ่น เปลี่ยนท่า ส่งแผ่น และส่งสัญลักษณ์ ✓ / ↻ / …
6. มิซารุอ่านแผ่นแล้วพิมพ์เล่าต่อ คิคาซารุวาดด้วยเมาส์หรือกล้อง
7. เปิดแนวคิดระหว่างเกม เกมพัก กลับออกแล้วกดเล่นต่อ
8. ลองจอแคบและคีย์บอร์ด Tab/Enter ตรวจปุ่มไม่ถูกตัดและอ่านทุกช่องได้
9. จบรอบ ดูคำถามสะท้อนคิด แล้วเปลี่ยนมุมมองทั้งสามตนใน Lobby

สถานะรอบแก้ไขนี้: ตรวจ typecheck, tests และ production build แล้ว;
ยังไม่ทดสอบด้วย browser automation หรือกล้อง/ไมค์จริง
